# 上线部署剩余事项清单

## 结论

当前项目已有部署基础，包括生产配置文件、环境变量示例、Docker Compose 示例、Nginx 反向代理配置和数据库初始化脚本。但按真实生产上线标准，上线前仍需完成安全配置、生产联调、核心流程回归验证、备份回滚方案，以及日志排查能力确认后再发布。

本清单只用于说明上线前最后还必须完成什么，以及如何验收；不替代实际配置修改、测试补充或部署演练。

## 当前已发现的上线风险

- [x] JWT 已改为配置化读取，生产必须替换默认 `JWT_SECRET`，并使用足够强度的随机密钥。
- [x] CORS 已改为配置化读取，生产必须将 `CORS_ALLOWED_ORIGIN_PATTERNS` 限制为真实前端域名。
- [x] 图片上传已统一走 OSS，生产必须确认 `OSS_ENDPOINT`、`OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`、`OSS_BUCKET_NAME`、`OSS_DOMAIN` 均配置正确。
- [ ] `deploy/docker-compose.prod.yml` 和 `.env.example` 中仍存在 `change-me`、`root-change-me` 等示例密码，上线前必须替换为真实强密码。
- [ ] `forum/forum-server/src/main/resources/application.yml` 默认激活 `dev`，生产启动必须显式设置 `SPRING_PROFILES_ACTIVE=prod`，并在启动日志中确认实际 profile。

## P0 必须完成后才能上线

- [ ] 安全配置
  - [ ] 替换所有数据库、Root、OSS、JWT 等示例密钥或固定密钥。
  - [ ] 关闭生产环境不需要暴露的调试能力和接口文档入口。
  - [ ] CORS 只允许真实前端域名，不允许通配来源携带凭证访问。

- [ ] 生产环境变量
  - [ ] 明确设置 `SPRING_PROFILES_ACTIVE=prod`。
  - [ ] 设置 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`ES_URIS`。
  - [ ] 补齐 `OSS_ENDPOINT`、`OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`、`OSS_BUCKET_NAME`、`OSS_DOMAIN`。

- [ ] 数据库初始化
  - [ ] 在生产数据库执行 `forum/sql/init.sql`。
  - [ ] 执行 `forum/sql/notification.sql`。
  - [ ] 执行 `forum/sql/v3_post_location.sql`。
  - [ ] 确认表结构、初始数据和字符集符合预期。

- [ ] OSS 上传配置
  - [ ] 确认 OSS Bucket、Endpoint、访问域名和访问密钥可用。
  - [ ] 确认后端上传头像和帖子图片后返回 OSS URL。
  - [ ] 上传后重启服务，确认头像和图片仍可通过 OSS URL 访问。

- [ ] 前后端构建
  - [ ] 后端构建成功，并生成可部署 Jar。
  - [ ] 前端构建成功，并生成 `forum-web/dist/`。
  - [ ] 确认 Nginx 静态资源目录指向最新 `dist`。

- [ ] 生产联调
  - [ ] 前端能通过 `/api/` 正常访问后端。
  - [ ] OSS 图片 URL 能正常回显。
  - [ ] 登录态、跨域 Cookie 或 Authorization Header 行为符合生产域名配置。
  - [ ] Elasticsearch 可连通，搜索功能按预期返回结果。

- [ ] 核心流程回归
  - [ ] 注册、登录、Token 自动续期、退出。
  - [ ] 发帖、编辑、删帖、详情、列表、分类、标签。
  - [ ] 评论、回复、点赞、收藏、通知跳转。
  - [ ] 搜索、搜索建议、ES 重建索引。
  - [ ] 头像/图片上传与部署后回显。
  - [ ] 管理后台用户、帖子、评论、分类管理。
  - [ ] 未登录访问、普通用户访问管理后台、非法资源访问。

- [ ] 备份与回滚
  - [ ] 上线前完成 MySQL 全量备份。
  - [ ] 保留上一版本后端 Jar、前端 `dist` 和 Nginx 配置。
  - [ ] 明确回滚步骤、负责人和回滚触发条件。
  - [ ] 至少演练一次数据库备份恢复或在测试环境验证恢复流程。

## P1 上线前强烈建议完成

- [ ] 基础日志检查
  - [ ] 确认后端启动日志能看到 profile、端口、数据库连接、ES 连接结果。
  - [ ] 确认业务异常、登录失败、上传失败、ES 失败有可定位日志。
  - [ ] 确认 Nginx access/error 日志路径和权限。

- [ ] 异常排查路径
  - [ ] 明确前端白屏、接口 500、接口 401/403、上传失败、搜索失败的排查入口。
  - [ ] 准备常用排查命令，例如查看容器日志、后端日志、Nginx 日志和数据库连接。

- [ ] 性能冒烟
  - [ ] 首页、帖子列表、详情页、搜索页在真实数据量下响应可接受。
  - [ ] 图片上传大小限制和 Nginx `client_max_body_size` 与后端 multipart 限制一致。
  - [ ] 数据库连接池配置满足预期并发。

- [ ] 浏览器兼容
  - [ ] 使用 Chrome、Edge、Safari 或移动端浏览器检查核心页面。
  - [ ] 检查登录、发帖、上传、管理后台在目标浏览器无明显样式或交互问题。

- [ ] ES 索引重建验证
  - [ ] 确认 ES 服务重启后数据仍保留。
  - [ ] 执行一次全量重建索引。
  - [ ] 对比数据库帖子数量和 ES 可搜索数据量。

## P2 上线后继续优化

- [ ] 自动化测试
  - [ ] 为登录、发帖、评论、搜索、管理后台等核心接口补充后端测试。
  - [ ] 为前端核心路径补充端到端测试。

- [ ] 监控告警
  - [ ] 增加服务存活、接口错误率、响应时间、数据库连接、磁盘空间告警。
  - [ ] 增加 ES 健康状态和索引异常告警。

- [ ] 日志归档
  - [ ] 配置日志切割、保留周期和集中检索。
  - [ ] 避免日志输出敏感信息。

- [ ] 前端包体优化
  - [ ] 分析 `npm run build` 的 chunk 体积。
  - [ ] 对明显过大的依赖或页面做按需加载。

- [ ] 专项压测
  - [ ] 对登录、帖子列表、详情、搜索、上传等高频接口做压测。
  - [ ] 根据压测结果调整数据库索引、连接池、JVM 参数和缓存策略。

## 可直接执行的验收命令

后端构建：

```bash
cd forum
mvn clean package
```

前端构建：

```bash
cd forum-web
npm run build
```

Docker Compose 启动：

```bash
cd deploy
docker compose -f docker-compose.prod.yml up -d
```

Elasticsearch 连通性检查：

```bash
curl http://127.0.0.1:9200
```
